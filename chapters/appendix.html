Concurrency II
by Robert C. Martin

Concurrency মানে হলো একই সময়ে একাধিক কাজ চালানো। এই পরিশিষ্টে Concurrent Programming-এর গভীর বিষয়গুলো আলোচনা করা হয়েছে — Thread Management, Execution Path, Deadlock, ও Testing Strategy।

Client/Server এবং Threading Client/Server Threading Example

একটি সাধারণ Client/Server অ্যাপ্লিকেশনের পারফরম্যান্স বাড়াতে Threading কীভাবে ব্যবহার করা যায় সেটি দেখানো হয়েছে।

সমস্যা: Single-threaded Server ধীর — process(socket) শেষ না হওয়া পর্যন্ত পরবর্তী Client অপেক্ষা করে। যদি এটি I/O-bound হয় (Socket, Database ইত্যাদি), তাহলে Threading দিয়ে Throughput বাড়ানো যায়।

সতর্কতা: সরাসরি Thread তৈরি করলে কাজ করে, কিন্তু Naive — Thread-এর সংখ্যা সীমাহীন হতে পারে। তাছাড়া process মেথডে অনেক দায়িত্ব মিশে আছে: Socket Management, Client Processing, Threading Policy, Shutdown Policy।

ভালো সমাধান: দায়িত্ব আলাদা করুন (Single Responsibility Principle)। Thread Management আলাদা ক্লাসে রাখলে পরিবর্তন সহজ হয়। একটি ClientScheduler interface তৈরি করুন, তারপর Thread-per-request বা Executor-based implementation দিন:

✗ Thread-per-request (সরল) 
// ThreadPerRequestScheduler
Thread thread = new Thread(runnable);
thread.start();
✓ Executor-based (ভালো) 
// ExecutorClientScheduler
executor = Executors.newFixedThreadPool(
    availableThreads);
executor.execute(runnable);
টিপস

সব Concurrency কোড অল্প কিছু ক্লাসে কেন্দ্রীভূত রাখুন। Thread Management যে ক্লাস করবে, সেটি শুধু Thread Management করবে — অন্য কিছু নয়।

Execution Path ও Thread সমস্যা Execution Paths and Thread Problems

একটি সামান্য এক-লাইনের Java মেথড দিয়ে বোঝানো হয়েছে কীভাবে Thread সমস্যা হতে পারে:

public class IdGenerator {
    int lastIdUsed;
    public int incrementValue() {
        return ++lastIdUsed;
    }
}

যদি lastIdUsed = 93 থাকে এবং দুটি Thread একটি কল করে, তাহলে তৃতীয় ফলাফলটি সমস্যা — দুটি Thread একই মান পেয়েছে! কারণ ++ operator Atomic নয় — এটি Byte-code-এ ৮টি instruction-এ ভেঙে যায়। দুটি Thread-এ ৮টি করে instruction থাকলে মোট সম্ভাব্য পথের সংখ্যা 12,870!

সমাধান: synchronized কীওয়ার্ড ব্যবহার করলে সম্ভাব্য পথ মাত্র ২টি হয়ে যায়।

যা মনে রাখতে হবে: ++ (Pre/Post-increment) Atomic নয়। ৩২-bit int এর Assignment Atomic, কিন্তু ৬৪-bit long এর নয়। Shared Object কোথায় আছে, কোন কোন Concurrent Read/Update করে, ও কীভাবে Guard করবেন — এই তিনটি জানা জরুরি।

লাইব্রেরি পরিচিতি Knowing Your Library

Executor Framework: Java ৫-র java.util.concurrent প্যাকেজে Executor Framework আছে। নিজে Thread Pool তৈরি না করে এটি ব্যবহার করুন। Runnable ও Callable দুটোই সাপোর্ট করে। Future ব্যবহার করে একাধিক স্বতন্ত্র কাজ সমান্তরালে চালাতে পারবেন।

Nonblocking Solutions: AtomicInteger, AtomicBoolean, AtomicReference ব্যবহার করলে synchronized এর চেয়ে প্রায় সবসময় ভালো Performance পাবেন। এগুলো Compare and Swap (CAS) অপারেশন ব্যবহার করে — যেটি Optimistic Locking-এর মতো।

Deadlock প্রতিরোধ Preventing Deadlock

Deadlock মানে হলো দুই বা ততোধিক Thread পরস্পরের Resource-এর জন্য অপেক্ষা করে, ও কেউ এগোতে পারে না। Deadlock হতে চারটি শর্ত একসাথে লাগে:

শর্তভাঙার উপায়
Mutual ExclusionAtomicInteger-এর মতো Concurrent Resource ব্যবহার করুন
Lock & Waitসব Resource না পেলে সব ছেড়ে দিন, আবার চেষ্টা করুন
No PreemptionResource ব্যস্ত হলে মালিককে ছেড়ে দিতে বলুন
Circular Waitসবাই একই ক্রমে Resource নেবে (সবচেয়ে সাধারণ সমাধান)
টিপস

যেকোনো একটি শর্ত ভাঙলেই Deadlock হবে না। সাধারণত Circular Wait ভাঙা সবচেয়ে সহজ — সব Thread একই ক্রমে Resource নেবে।

Multithreaded কোড টেস্টিং Testing Multithreaded Code

Concurrent Bug ধরা অত্যন্ত কঠিন। একটি সাধারণ nextId++ সমস্যা ধরতে ১০ লক্ষের বেশি Iteration লাগতে পারে। কিছু কৌশল:

১. Monte Carlo Testing: বিভিন্ন Random Tuning Value দিয়ে বারবার Test চালান। Continuous Integration Server-এ চালিয়ে রাখুন। একবার Fail করলে — Bug আছে।

২. Multi-platform Testing: সব Target Platform-এ বারবার Test চালান। ভিন্ন OS, ভিন্ন JVM-এ ভিন্ন ফলাফল আসতে পারে।

৩. Varying Load Testing: Production-এর মতো Load দিয়ে টেস্ট করুন।

৪. Tool ব্যবহার করুন: IBM-এর ConTest-এর মতো Tool ব্যবহার করলে Threading Bug অনেক দ্রুত ধরা পড়ে। ConTest ব্যবহারের পর সাফল্যের হার ১ কোটি Iteration-এ ১ বার থেকে মাত্র ৩০ Iteration-এ ১ বার হয়ে গেছে।

★ মূল ধারণা সারসংক্ষেপ Key Concepts

★ Thread Management কোড আলাদা রাখুন
Single Responsibility Principle — Thread Management যে ক্লাস করবে, সেটি শুধু Thread Management করবে।
★ synchronized যতটা সম্ভব কম ব্যবহার করুন
শুধু Critical Section-এ। java.util.concurrent প্যাকেজ ব্যবহার করুন — নিজে Thread Pool তৈরি করবেন না।
★ Nonblocking Solution পছন্দ করুন
AtomicInteger, AtomicBoolean — এগুলো synchronized-এর চেয়ে প্রায় সবসময় ভালো Performance দেয়।
★ Deadlock এড়াতে চারটি শর্তের যেকোনো একটি ভাঙুন
সাধারণত Circular Wait ভাঙা সবচেয়ে সহজ — সব Thread একই ক্রমে Resource নেবে।
★ Threading Bug ধরতে বিশেষ Tool ও Strategy ব্যবহার করুন
Monte Carlo Testing, Multi-platform Testing, ConTest-এর মতো Tool — এগুলো Threading Bug দ্রুত ধরতে সাহায্য করে।
