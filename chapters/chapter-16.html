SerialDate রিফ্যাক্টরিং
Refactoring SerialDate
by Robert C. Martin

এই অধ্যায়ে Robert C. Martin একটি ওপেন-সোর্স ক্লাস (SerialDate) নিয়ে Professional Code Review করেছেন। Refactoring মানে হলো কোডের বাহ্যিক আচরণ না বদলে তার অভ্যন্তরীণ গঠন উন্নত করা। এখানে "প্রথমে কাজ করাও, তারপর সুন্দর করো" — এই নীতি অনুসরণ করা হয়েছে।

প্রথমে কাজ করাও First, Make It Work

Refactoring শুরু করার আগে, প্রথম কাজ হলো পর্যাপ্ত Unit Test লেখা। লেখক দেখলেন যে বিদ্যমান টেস্ট মাত্র ৫০% কোড কভার করে। তাই তিনি নিজে নতুন করে টেস্ট লিখলেন যা ৯২% কভারেজ দিলো।

টিপস

Refactoring-এর আগে সবসময় শক্তিশালী Test Suite তৈরি করুন। Test ছাড়া Refactoring করা অনেকটা জাল ছাড়া দড়ির উপর হাঁটার মতো।

টেস্ট লেখার সময় বেশ কিছু Bug ধরা পড়লো। যেমন: getFollowingDayOfWeek মেথডে একটি Boundary Condition Error ছিল — >= এর পরিবর্তে > ব্যবহার করা হয়েছিলো।

তারপর সুন্দর করো Then Make It Right

কোড ঠিকমতো কাজ করার পর, লেখক একে ধাপে ধাপে পরিষ্কার করেছেন। এখানে প্রধান Refactoring টিপসগুলো:

১. অপ্রয়োজনীয় কমেন্ট মুছে ফেলুন: Change History কমেন্ট আর দরকার নেই কারণ আমাদের Source Code Control (যেমন Git) আছে। Redundant Comment মানে হলো এমন কমেন্ট যা কোড নিজেই বলে দিচ্ছে — এগুলো মিথ্যা তথ্য হয়ে যাওয়ার ঝুঁকি তৈরি করে।

২. সঠিক নামকরণ করুন: SerialDate নামটি Implementation নির্দেশ করে, কিন্তু এটি একটি Abstract Class। তাই এর নাম হওয়া উচিত DayDate — যা Abstraction Level-এ সঠিক। toSerial() এর বদলে getOrdinalDay() অনেক বেশি বর্ণনামূলক।

৩. int constant-এর বদলে Enum ব্যবহার করুন: পুরোনো static final int গুলোকে Enum-এ রূপান্তর করলে Type Safety পাওয়া যায় ও ভুল value পাঠানোর সম্ভাবনা কমে।

৪. Abstract Factory Pattern প্রয়োগ করুন: Base Class (DayDate) সরাসরি SpreadsheetDate তৈরি করছিলো — এটি ভুল কারণ Base Class-এর তার Derivative সম্পর্কে জানা উচিত নয়। সমাধান হলো DayDateFactory তৈরি করা।

৫. Static মেথডকে Instance মেথডে পরিবর্তন করুন: addDays, addMonths ইত্যাদি মেথড DayDate-র variable নিয়ে কাজ করে, তাই এগুলো Static না হয়ে Instance Method হওয়া উচিত। তবে নাম পরিবর্তন করতে হবে যাতে বোঝা যায় Original Object পরিবর্তিত হচ্ছে না:

// date.plusDays(5) — স্পষ্ট (নতুন date ফেরত আসবে)
public DayDate plusDays(int days) {
    return DayDateFactory.makeDate(toOrdinal() + days);
}

৬. Dead Code মুছে ফেলুন: যেসব মেথড কেউ ব্যবহার করে না — সাহসের সাথে মুছে ফেলুন। Source Control-এ সব সুরক্ষিত আছে।

৭. Switch-কে Polymorphism দিয়ে প্রতিস্থাপন করুন: isInRange মেথডের switch statement-কে DateInterval enum-এর মধ্যে polymorphic behavior হিসেবে সরানো হয়েছে।

★ মূল ধারণা সারসংক্ষেপ Key Concepts

★ Boy Scout Rule অনুসরণ করুন
কোড যেমন পেয়েছেন তার চেয়ে একটু পরিষ্কার করে রেখে যান।
★ Refactoring-এর আগে Test Coverage বাড়ান
Test ছাড়া Refactoring বিপজ্জনক। ৫০% থেকে ৯২% কভারেজে নিয়ে যান।
★ ছোট ছোট ধাপে Refactor করুন
প্রতিটি ধাপের পর Test চালান করুন। নামকরণ, Abstraction Level, ও Design Pattern — এই তিনটি বিষয়ে মনোযোগ দিন।
★ Enum ব্যবহার করুন
int constant-এর বদলে Enum ব্যবহার করলে Type Safety পাওয়া যায়।
★ Base Class Derivative সম্পর্কে জানবে না
দরকার হলে Abstract Factory Pattern ব্যবহার করুন।
★ Dead Code সাহসের সাথে মুছুন
Source Control-এ সব সুরক্ষিত — ভয় পাবেন না।
