ফরম্যাটিং
Formatting
by Robert C. Martin
যখন কেউ কোডের ভেতরে উঁকি দেয়, আমরা চাই তারা পরিপাটি, সামঞ্জস্যপূর্ণ ও সূক্ষ্ম যন্ত্রের ছাপ দেখে মুগ্ধ হোক।

Formatting-এর উদ্দেশ্য The Purpose of Formatting

প্রথমেই পরিষ্কার করা দরকার: code formatting গুরুত্বপূর্ণ। এত গুরুত্বপূর্ণ যে এটাকে উপেক্ষা করা যায় না, আবার ধর্মীয়ভাবে মানাও ঠিক নয়। Code formatting হলো communication (যোগাযোগ) সম্পর্কে, আর communication হলো professional developer-এর প্রথম কাজ।

আপনি হয়তো ভাবছেন "কাজ করানো"ই প্রথম কাজ। কিন্তু আজ যে functionality তৈরি করছেন, সেটা পরবর্তী release-এ বদলে যাওয়ার ভালো সম্ভাবনা আছে। কিন্তু কোডের readability (পাঠযোগ্যতা) ভবিষ্যতের সব পরিবর্তনকে প্রভাবিত করবে। মূল কোড চিনতে না পারা গেলেও আপনার coding style ও discipline টিকে থাকবে।

Vertical Formatting উল্লম্ব বিন্যাস

একটি source file কত বড় হওয়া উচিত? বিভিন্ন Java project বিশ্লেষণে দেখা যায়, FitNesse প্রকল্পে (প্রায় ৫০,০০০ লাইন) বেশিরভাগ file ২০০ লাইনের কম, সর্বোচ্চ ৫০০ লাইন। এটা কঠিন নিয়ম নয়, তবে অত্যন্ত কার্যকর। ছোট file সাধারণত বড় file-এর চেয়ে সহজে বোঝা যায়।

The Newspaper Metaphor (সংবাদপত্রের রূপক)

একটি ভালো সংবাদপত্রের মতো কোড সাজাতে হবে। উপরে headline — যেটা পড়ে সংক্ষেপে বোঝা যায় কী আছে। প্রথম paragraph-এ সারাংশ। নিচে যত যাবেন, বিস্তারিত বাড়বে।

Source file-ও তেমনই হওয়া উচিত। নাম দেখেই বুঝতে হবে সঠিক module কিনা। উপরে high-level concept ও algorithm থাকবে। নিচে যত যাবেন, detail বাড়বে, সবশেষে lowest level function ও বিবরণ।

Vertical Openness Between Concepts (ধারণার মাঝে উল্লম্ব ফাঁকা)

প্রতিটি লাইন একটি expression বা clause, আর লাইনগুলো একটি সম্পূর্ণ চিন্তা প্রকাশ করে। চিন্তাগুলোকে blank line দিয়ে আলাদা করতে হয়:

Blank Line দিয়ে Concept আলাদা
package fitnesse.wikitext.widgets;

import java.util.regex.*;

public class BoldWidget extends ParentWidget {
    public static final String REGEXP = "'''.+?'''";
    private static final Pattern pattern = Pattern.compile("'''(.+?)'''",
        Pattern.MULTILINE + Pattern.DOTALL
    );

    public BoldWidget(ParentWidget parent, String text) throws Exception {
        super(parent);
        Matcher match = pattern.matcher(text);
        match.find();
        addChildWidgets(match.group(1));
    }

    public String render() throws Exception {
        StringBuffer html = new StringBuffer("<b>");
        html.append(childHtml()).append("</b>");
        return html.toString();
    }
}

Package declaration, import, ও প্রতিটি function-এর মাঝে blank line। এই সাধারণ নিয়ম কোডের visual layout-কে ভীষণ প্রভাবিত করে। Blank line না থাকলে কোড একটা অপঠনযোগ্য mass-এ পরিণত হয়।

Vertical Density (উল্লম্ব ঘনত্ব)

Openness যদি concept আলাদা করে, তাহলে density নিকট সম্পর্ক বোঝায়। নিকটভাবে সম্পর্কিত লাইন কাছাকাছি থাকবে। অপ্রয়োজনীয় comment মাঝে ঢুকিয়ে সম্পর্ক ভাঙা যাবে না:

Comment সম্পর্ক ভেঙে দিচ্ছে
public class ReporterConfig {
    /**
     * The class name of the
     * reporter listener
     */
    private String m_className;

    /**
     * The properties of the
     * reporter listener
     */
    private List<Property> m_properties
        = new ArrayList<Property>();
}
ঘনত্ব বজায় — কাছাকাছি
public class ReporterConfig {
    private String m_className;
    private List<Property> m_properties
        = new ArrayList<Property>();
}

Vertical Distance (উল্লম্ব দূরত্ব)

আপনি কি কখনো কোনো class-এ function থেকে function-এ, উপরে-নিচে scroll করতে করতে হারিয়ে গেছেন? এটা হতাশাজনক, কারণ আপনি system বুঝতে চাইছেন কিন্তু সময় ব্যয় করছেন টুকরো খুঁজতে। নিকটভাবে সম্পর্কিত concept গুলো vertically কাছাকাছি রাখতে হবে।

Variable Declarations

Variable তার ব্যবহারের যতটা সম্ভব কাছে declare করতে হবে। আমাদের function যেহেতু ছোট, তাই local variable function-এর শুরুতে থাকবে। Loop control variable সাধারণত loop statement-এর মধ্যেই declare হবে।

Instance Variables

Class-এর শুরুতে declare করতে হবে। Java-তে এটাই convention। গুরুত্বপূর্ণ বিষয় হলো, সব instance variable একটি সুপরিচিত জায়গায় থাকবে, যাতে সবাই সহজেই কোথায় দেখতে হবে জানে।

Dependent Functions

যদি একটি function অন্য একটিকে call করে, তারা vertically কাছাকাছি থাকবে, এবং caller callee-এর উপরে থাকবে। এটা program-এ স্বাভাবিক প্রবাহ দেয়:

Caller উপরে, Callee নিচে
public Response makeResponse(FitNesseContext context, Request request)
        throws Exception {
    String pageName = getPageNameOrDefault(request, "FrontPage");
    loadPage(pageName, context);
    if (page == null)
        return notFoundResponse(context, request);
    else
        return makePageResponse(context);
}

private String getPageNameOrDefault(Request request, String defaultPageName) {
    String pageName = request.getResource();
    if (StringUtil.isBlank(pageName))
        pageName = defaultPageName;
    return pageName;
}

protected void loadPage(String resource, FitNesseContext context)
        throws Exception {
    WikiPagePath path = PathParser.parse(resource);
    crawler = context.root.getPageCrawler();
    crawler.setDeadEndStrategy(new VirtualEnabledPageCrawler());
    page = crawler.getPage(context.root, path);
    if (page != null)
        pageData = page.getData();
}

Conceptual Affinity (ধারণাগত সম্পর্ক)

কিছু কোড কাছাকাছি রাখা উচিত কারণ তারা একই ধরনের কাজ করে। যেমন কয়েকটি function যারা common naming scheme ভাগ করে এবং basic task-এর variation করে:

সম্পর্কিত Function কাছাকাছি
static public void assertTrue(String message, boolean condition) {
    if (!condition) fail(message);
}
static public void assertTrue(boolean condition) {
    assertTrue(null, condition);
}
static public void assertFalse(String message, boolean condition) {
    assertTrue(message, !condition);
}
static public void assertFalse(boolean condition) {
    assertFalse(null, condition);
}

Vertical Ordering (উল্লম্ব ক্রম)

Function call dependency নিচের দিকে point করবে। অর্থাৎ, যে function call করে সে উপরে, যাকে call করা হয় সে নিচে। Newspaper article-এর মতো: সবচেয়ে গুরুত্বপূর্ণ concept প্রথমে, সবচেয়ে কম polluting detail শেষে।

Horizontal Formatting অনুভূমিক বিন্যাস

একটি লাইন কত লম্বা হওয়া উচিত? বিভিন্ন project বিশ্লেষণে দেখা যায় programmer-রা ছোট লাইন পছন্দ করেন। পুরোনো ৮০ character-এর Hollerith limit কিছুটা arbitrary, ১০০ বা ১২০ পর্যন্ত ঠিক আছে। কিন্তু তার বেশি সাবধানতা দরকার।

Horizontal Openness and Density (অনুভূমিক ফাঁকা ও ঘনত্ব)

White space দিয়ে সম্পর্কিত জিনিস কাছে রাখতে হবে ও অসম্পর্কিত জিনিস আলাদা করতে হবে:

Space ব্যবহারের নিয়ম
private void measureLine(String line) {
    lineCount++;
    int lineSize = line.length();
    totalChars += lineSize;
    lineWidthHistogram.addLine(lineSize, lineCount);
    recordWidestLine(lineSize);
}

Assignment operator-এর দুপাশে space — কারণ দুটো আলাদা element। কিন্তু function name ও opening parenthesis-এর মধ্যে space নেই — কারণ function ও তার argument নিকটভাবে সম্পর্কিত।

Operator precedence বোঝাতেও white space ব্যবহার করা যায়:

Precedence দেখানো
return (-b + Math.sqrt(determinant)) / (2*a);

Factor-এর মধ্যে space নেই (উচ্চ precedence), term-এর মধ্যে space আছে (নিম্ন precedence)।

Horizontal Alignment (অনুভূমিক সারিবদ্ধকরণ)

Variable name ও rvalue গুলোকে column-এ সাজানো — এটা করবেন না। এটা ভুল জিনিস highlight করে। আপনি variable name পড়তে গিয়ে type miss করেন। আধুনিক reformatting tool-ও alignment সরিয়ে দেয়। যদি list এত লম্বা যে alignment দরকার, তাহলে আসল সমস্যা হলো list-এর দৈর্ঘ্য — class-কে ভাঙতে হবে।

Indentation (ইন্ডেন্টেশন)

Source file একটি hierarchy: file level, class level, method level, block level। প্রতিটি level-এ কোড ডান দিকে সরে যায়। Programmer-রা indentation-এর উপর ব্যাপকভাবে নির্ভর করেন — এটা দিয়ে তারা scope বোঝেন, প্রাসঙ্গিক scope skip করেন। Indentation ছাড়া program পড়া মানুষের পক্ষে প্রায় অসম্ভব।

Breaking Indentation

ছোট if statement বা while loop-এর indentation ভাঙার প্রলোভন হয়। কিন্তু প্রায় সবসময়ই indentation বজায় রাখাটাই ভালো:

Indentation ভাঙা
public CommentWidget(ParentWidget parent,
  String text){super(parent, text);}
public String render() throws Exception
  {return ""; }
Indentation বজায়
public CommentWidget(ParentWidget parent,
        String text) {
    super(parent, text);
}

public String render() throws Exception {
    return "";
}

Dummy Scopes

while বা for loop-এর body যদি dummy (শূন্য) হয়, সেই semicolon-কে নতুন লাইনে indented করে রাখতে হবে, না হলে চোখে পড়বে না:

Dummy Scope
while (dis.read(buf, 0, readBufferSize) != -1)
    ;

Team Rules দলের নিয়ম

প্রত্যেক programmer-এর পছন্দের formatting নিয়ম থাকে। কিন্তু দলে কাজ করলে দলের নিয়ম চূড়ান্ত।

দলের সবাই মিলে একটি formatting style ঠিক করবেন, তারপর সবাই সেটা মানবেন।

FitNesse প্রকল্পে দলের সবাই মিলে প্রায় ১০ মিনিটে coding style ঠিক করে নিয়েছিলেন — brace কোথায় যাবে, indent size কত হবে, class-এ method-এ variable-এর naming convention কী। তারপর IDE-এর code formatter-এ সেই নিয়ম set করে সবাই কাজ শুরু করলেন।

ভালো software system মানে কিছু সুপঠ্য document-এর সমাহার, যা পড়তে ভালো লাগে। একই style ও সামঞ্জস্য পূর্ণ হওয়া দরকার। এলোমেলো style-এ লেখা code base-কে দেখে মনে হয় একগাদা লোক যে যার মতো করে লিখেছে।

★ মূল ধারণা সারসংক্ষেপ Key Concepts

★ Formatting = Communication
Code formatting হলো communication (যোগাযোগ) — এটা professional developer-এর প্রথম কর্তব্য।
★ Newspaper Metaphor
Source file-কে newspaper-এর মতো সাজাও — উপরে high-level concept, নিচে detail।
★ Vertical Openness ও Density
সম্পর্কিত concept কাছাকাছি রাখো, সম্পর্কহীন concept ফাঁকা লাইন দিয়ে আলাদা করো।
★ Vertical Distance
সম্পর্কিত function কাছাকাছি রাখো। Caller উপরে, callee নিচে। Variable declaration ব্যবহারের কাছে।
★ Horizontal Formatting
লাইন ১২০ character-এর বেশি নয়। White space দিয়ে সম্পর্ক ও পৃথকতা বোঝাও। Indentation গুরুত্বপূর্ণ।
★ Team Rules
দলে কাজ করলে দলের নিয়ম মানো, ব্যক্তিগত পছন্দ নয়। IDE formatter-এ নিয়ম set করো।
