TL;DR

JUnit's ComparisonCompactor turns two differing strings into a compact diff like <...B[X]D...>. The code was already good and 100% test-covered — yet the Boy Scout Rule says leave it cleaner than you found it. Step by step Martin drops the f member prefixes, encapsulates a bare conditional, gives variables unambiguous names, inverts a negative, renames compact to the honest formatCompactedComparison, fixes the off-by-one +1s (revealing a hidden dead-code bug), and finally splits the module into clean analysis and synthesis functions. Refactoring is iterative trial and error — some earlier decisions even get reversed.

15.1The Tests First

The test cases define the requirements better than prose. Given two strings that differ, the compactor exposes the difference with context, ellipses, and [ ] deltas:

public void testMessage() {
  String failure= new ComparisonCompactor(0, "b", "c").compact("a");
  assertTrue("a expected:<[b]> but was:<[c]>".equals(failure));
}
public void testStartAndEndContextWithEllipses() {
  String failure=
    new ComparisonCompactor(1, "abcde", "abfde").compact(null);
  assertEquals("expected:<...b[c]d...> but was:<...b[f]d...>", failure);
}
100% coverage breeds respect

A coverage analysis showed every line, if, and for loop is exercised by the tests — high confidence that the code works, and high respect for the authors' craftsmanship.

15.2The Original Module

The original is nicely partitioned and reasonably expressive — but has f-prefixed members, a bare opening conditional, some strange +1s, and long expressions:

public class ComparisonCompactor {
  private static final String ELLIPSIS = "...";
  private static final String DELTA_END = "]";
  private static final String DELTA_START = "[";
  private int fContextLength;
  private String fExpected;
  private String fActual;
  private int fPrefix;
  private int fSuffix;
  public ComparisonCompactor(int contextLength,
      String expected, String actual) {
    fContextLength = contextLength;
    fExpected = expected;
    fActual = actual;
  }
  public String compact(String message) {
    if (fExpected == null || fActual == null || areStringsEqual())
      return Assert.format(message, fExpected, fActual);
    findCommonPrefix();
    findCommonSuffix();
    String expected = compactString(fExpected);
    String actual = compactString(fActual);
    return Assert.format(message, expected, actual);
  }
  // findCommonPrefix / findCommonSuffix /
  // compactString / computeCommonPrefix /
  // computeCommonSuffix with several "+1"s ...
}

The steps: drop the f prefixes (modern IDEs make scope encoding redundant); encapsulate the conditional into a named shouldNotBeCompacted(); give the locals unambiguous names (compactExpected, not this.expected shadowing); invert the negative for readability; and rename compact → formatCompactedComparison, since the function returns a formatted message and may not compact at all — the old name hid that side effect.

15.4Fixing the +1s Reveals a Hidden Bug

Renaming suffixIndex to suffixLength exposed that the variable was 1-based, not a true length — the source of all those +1s. Fixing it (a -1 in charFromEnd, <= in suffixOverlapsPrefix) made the code make sense — and uncovered dead code:

An if that never did anything

With the fix, if (suffixLength > 0) finally made sense — meaning it hadn't before, because suffixIndex could never be less than one. Both guarding if statements in compactString were nonfunctional. Commenting them out and running the tests: they passed. So both were removed, simplifying the function to pure composition:

private String compactString(String source) {
  return
    computeCommonPrefix() +
    DELTA_START +
    source.substring(prefixLength, source.length() - suffixLength) +
    DELTA_END +
    computeCommonSuffix();
}

15.5The Final Result

After many small cleanups, the module separates into analysis functions and synthesis functions, topologically sorted so each definition appears just after its use:

public class ComparisonCompactor {
  private static final String ELLIPSIS = "...";
  private static final String DELTA_END = "]";
  private static final String DELTA_START = "[";
  private int contextLength;
  private String expected;
  private String actual;
  private int prefixLength;
  private int suffixLength;
  public ComparisonCompactor(
      int contextLength, String expected, String actual) {
    this.contextLength = contextLength;
    this.expected = expected;
    this.actual = actual;
  }
  public String formatCompactedComparison(String message) {
    String compactExpected = expected;
    String compactActual = actual;
    if (shouldBeCompacted()) {
      findCommonPrefixAndSuffix();
      compactExpected = compact(expected);
      compactActual = compact(actual);
    }
    return Assert.format(message, compactExpected, compactActual);
  }
  // --- analysis ---
  private boolean shouldBeCompacted() {
    return !shouldNotBeCompacted();
  }
  private boolean shouldNotBeCompacted() {
    return expected == null || actual == null || expected.equals(actual);
  }
  private void findCommonPrefixAndSuffix() {
    findCommonPrefix();
    suffixLength = 0;
    for (; !suffixOverlapsPrefix(); suffixLength++) {
      if (charFromEnd(expected, suffixLength) != charFromEnd(actual, suffixLength))
        break;
    }
  }
  private char charFromEnd(String s, int i) {
    return s.charAt(s.length() - i - 1);
  }
  private boolean suffixOverlapsPrefix() {
    return actual.length() - suffixLength <= prefixLength ||
           expected.length() - suffixLength <= prefixLength;
  }
  private void findCommonPrefix() {
    prefixLength = 0;
    int end = Math.min(expected.length(), actual.length());
    for (; prefixLength < end; prefixLength++)
      if (expected.charAt(prefixLength) != actual.charAt(prefixLength))
        break;
  }
  // --- synthesis ---
  private String compact(String s) {
    return new StringBuilder()
      .append(startingEllipsis())
      .append(startingContext())
      .append(DELTA_START)
      .append(delta(s))
      .append(DELTA_END)
      .append(endingContext())
      .append(endingEllipsis())
      .toString();
  }
  private String startingEllipsis() {
    return prefixLength > contextLength ? ELLIPSIS : "";
  }
  private String startingContext() {
    int contextStart = Math.max(0, prefixLength - contextLength);
    int contextEnd = prefixLength;
    return expected.substring(contextStart, contextEnd);
  }
  private String delta(String s) {
    int deltaStart = prefixLength;
    int deltaEnd = s.length() - suffixLength;
    return s.substring(deltaStart, deltaEnd);
  }
  private String endingContext() {
    int contextStart = expected.length() - suffixLength;
    int contextEnd = Math.min(contextStart + contextLength, expected.length());
    return expected.substring(contextStart, contextEnd);
  }
  private String endingEllipsis() {
    return (suffixLength > contextLength ? ELLIPSIS : "");
  }
}
Refactoring is iterative trial and error

Martin reversed several earlier decisions — inlining some extracted methods back into formatCompactedComparison and flipping the sense of shouldNotBeCompacted. This is typical: one refactoring leads to another that undoes the first, inevitably converging on something worthy of a professional.

15.6Principles & Rules

Boy Scout Rule

No module is immune from improvement — leave it cleaner than you found it.

Drop Redundant Encodings

Member prefixes like f are noise modern IDEs make unnecessary.

Encapsulate & Name Honestly

Wrap bare conditionals; name functions for what they really do (side effects included).

Cleaning Surfaces Bugs

Fixing the +1s exposed dead, never-true guard clauses.

Separate Analysis from Synthesis

Group and order functions so each appears just after it's used.

15.7Common Mistakes

"It's already good, leave it"

Skipping improvement on decent code — the Boy Scout Rule still applies.

Misleading function names

compact hid that it formats and may not compact — rename to reveal intent.

1-based "length" variables

suffixIndex masquerading as a length spawned scattered +1s and a hidden bug.

Leaving non-functional guards

Dead if clauses that can never be false add noise and confusion.

15.8Conclusion & Takeaway

And so the Boy Scout Rule is satisfied — the module was left a bit cleaner than we found it. Not that it wasn't clean already; the authors did an excellent job. But no module is immune from improvement, and each of us has the responsibility to leave the code a little better than we found it.

One-liner Takeaway

Even excellent, fully-tested code can be left a little cleaner — that's the Boy Scout Rule, and it's everyone's responsibility.
